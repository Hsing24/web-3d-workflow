# 工作流樣本驗證計畫

先驗證 skill 的路線判斷，再驗證實際製作與網站呈現。所有製作案例初始狀態為「尚待執行」；文件及 skill 結構檢查不視為建模能力驗證。

## 驗證順序

| 次序 | 樣本 | 檢查問題 | 需要的執行能力 | 初始狀態 |
| --- | --- | --- | --- | --- |
| 1 | 有倒角與兩種表面的簡單展示物件 | 程序建模、光照與網站輸出能否形成可重複的小流程 | Blender CLI、網站引擎、瀏覽器 | 尚待執行 |
| 2 | 帶獨立旋轉部位的物件 | 局部支點、階層和命名是否在輸出與優化後保留 | 前項能力與互動控制 | 尚待執行 |
| 3 | 由一致參考圖生成的靜態形體 | 生成服務的形體、背面、薄件及修改成本是否適合目標 | 授權的生成服務與額度、Blender | 尚待執行 |
| 4 | 有一個可辨識變形區域的角色樣本 | 拓撲、權重與極端姿勢是否成立 | 符合角色類型的綁定能力 | 尚待執行 |
| 5 | 可調參數的抽象動態 | 程序路線的視覺、更新成本與目標裝置表現 | 網站著色與裝置量測 | 尚待執行 |
| 按需 | 小型場景與掃描物件 | 場景載入或掃描來源的額外要求 | 各路線實際需要的工具與素材 | 尚待執行 |

每個樣本先填寫需求模板，明確訂定品質、預算和目標裝置。不預設上述工具已存在，也不因其他模型通過而跳過本樣本驗證。

## Skill 行為檢查

以獨立的任務敘述使用 skill，觀察輸出的路線決定與規格。需要獨立代理時，限定只讀 skill 並寫入隔離的暫存目錄；此階段不執行付費服務或建模。

| 情境 | 應觀察的行為 |
| --- | --- |
| 只有一張概念圖，需靜態展示 | 區分可推定範圍、選候選路線並設多角度檢查 |
| 有尺寸圖且要求開合結構 | 以尺寸與分件為依據，保留支點，先測開合 |
| 已有綁定模型，只想減少網站成本 | 先檢查瓶頸，在副本優化，維持控制且測輸出 |
| 要求自然表情但沒有動作參考 | 補足關鍵動作資料，將變形列為早期關卡 |
| 只需滑鼠控制的抽象視覺 | 評估直接網站生成，不強制導入 GLB |
| 付費額度用完或多輪無改善 | 停止該方法，保留最佳候選與缺陷，提出替代路線 |

不以標題、措辭或固定答案判斷成功。檢查實際路線是否符合需求、是否保留重要資產結構，以及證據與結論是否相符。

## 每輪證據

保存已填規格、工具版本、來源授權、輸入輸出、參數、視覺對照、檢查結果和剩餘缺陷。網站量測需記錄硬體、瀏覽器與畫面條件。

驗證結果分開記錄「skill 決策、工具可呼叫、製作樣本、網站功能、裝置效能」。選擇主力生成服務前，使用相同素材與驗收條件比較候選品質、可修改性、費用和執行穩定性。

## 轉成可重用工具

樣本證明某操作可重複後，再建立對應腳本與入口。腳本需保存來源、支援任務參數、回報失敗、避免覆寫正式資產，並以實際案例驗證。

先實作已證明需要的能力，逐步加入生成服務、烘焙或批次驗收，避免先建立大量空的 adapter 與 skill。路線矩陣可隨實測結果調整，個別工具限制不提升為所有模型的通用規則。
