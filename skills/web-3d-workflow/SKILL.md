# Web 3D Workflow

以 AI 自主製作為主，依目標選擇素材、工具與製作路線，交付可修改的來源和在網站上成立的視覺成果。使用者決定目標與審美取捨；AI 主動整理素材、製作候選、檢查與修正。

## 依任務載入資料

- 判斷製作路線、準備素材時，讀 [路線矩陣](references/routes.md)。模型類別、精準度、動態和觀看方式一起決定路線。
- 選工具或接服務時，讀 [工具選擇](references/tooling.md)。工具清單是候選，能力與版本需在執行環境確認。
- 製作小樣本、修改資產、匯出或網站整合時，讀 [品質關卡](references/quality-gates.md) 的相應階段。
- 建立新任務規格時，複製 [製作需求模板](assets/production-brief.yaml) 至任務目錄填寫。簡單工作可只記錄有關欄位。

## 先確定產出與路線

從對話與既有檔案取得用途、品質參考、可見角度、最近觀看距離、動作、目標裝置、交付格式、資產來源與預算。缺少會改變製作方向的資訊才提問；不影響當前工作的欄位可先記錄假設並繼續。

區分三種狀態：使用者要求、已驗證事實、製作假設。AI 生成的多視角屬設計候選，需核對一致性；單張照片不能唯一決定背面、深度或內部結構。

選擇一條主要幾何來源：程序或 CAD、影像生成、既有基底、掃描。抽象效果也可直接在網站生成。再依需要疊加分件互動、骨骼變形、表情或大型場景處理。記錄選擇理由及一條可行的替代路線。

## 先證明最難的部分

先做能驗證核心風險的低成本樣本：例如近距離曲面反射、零件旋轉、最大變形或程序效果的裝置成本。使用接近正式展示尺寸的網站檢視器，提早確認相機、材質與載入相容性。

以中性材質和固定視角先檢查形體。需要變形時，在精細貼圖前測試中間值與極端動作。無法通過時回到形體、網格、控制或素材來源，避免靠表面細節掩蓋問題。

## 按需加工資產

先檢查，再選用修復、簡化、重拓撲、UV、烘焙、綁定等操作。保存來源，於可回退副本上加工。保留有意義的支點、座標、階層、命名、骨架與形態鍵。

不要把以下操作當成所有模型的預設：合併頂點、填洞、重新展 UV、合併材質、重新置中、套用所有變換或固定比例減面。它們可能破壞開口、接縫、貼圖、可動部位或動畫。

自動四邊形重拓撲只代表取得一種網格，仍需驗證變形。法線貼圖能補充表面明暗，不能補回輪廓、孔洞或視差。程序或腳本建模可用於有機形體，但是否採用取決於候選品質與修改效率。

## 交付並在網站驗收

保留可編輯母檔與網站版。檔案資產通常採 glTF／GLB；即時計算的程序效果則交付程式與參數。以既有網站技術整合，不為此工作任意更換框架。

先分析資產成本，再選壓縮或簡化方法。任何改變節點、精度、幾何、貼圖或動畫的優化，都需重查對應控制與視覺結果。保留網站版所需的解碼器和相容性設定。

在代表性目標裝置檢查載入、互動、幀時間與記憶體；區分實體裝置測量、模擬與估計。Headless 瀏覽器截圖可驗證呈現，不代表手機 GPU 效能。不能以面數或檔案大小單獨宣告效能通過。

## 修正與停止條件

每輪選定具體缺陷，保存前後對照及實際變更。依缺陷回到形體、材質、變形、匯出或網站階段，避免每輪重建全部內容。

在任務預算內自主迭代；使用者已授權的服務與額度可持續使用。未設定付費額度時先完成本機可做的規格與樣本準備，再釐清服務使用範圍。不得把金鑰寫入文件、腳本或輸出紀錄。

達到任務設定的費用、時間或重試上限時，停止該方法，交付最佳候選、剩餘缺陷和替代路線。缺少關鍵資料或連續無改善也應調整來源或方法，不能以重試次數代替品質證據。

## 完成條件

按任務範圍交付來源、網站資產或程序程式、必要貼圖與動畫、來源授權、工具與輸出版本、視覺對照及驗收結果。區分「檔案結構正確」「視覺通過」「網站功能通過」「目標裝置效能通過」。未驗證項目明確保留，避免把原型稱為正式完成品。
