# 製作與網站品質關卡

依任務範圍採用相關關卡。各關卡分別記錄「通過、未通過、尚待驗證、不適用」及理由；檔案結構正確不能代替視覺品質，桌面測量也不能代替手機實測。

## 需求與最小樣本

記錄品質參考、可見角度、顯示尺寸、最近觀看距離、互動與目標裝置。檔案大小、幀時間、載入與記憶體目標需包含測量條件，先由代表性樣本估算，再依產品需求訂定。

先證明最難的曲面、材質、動作或運行條件。樣本需有足夠代表性：省略會決定成本的毛髮、透明層、燈光或複雜著色時，不能把結果外推至完整成果。

## 形體

固定相機、構圖與光線，檢查中性材質、多角度及必要的線框。對照輪廓、部件數、比例、曲面連續性、孔洞與厚度。

保存使用角度的對照圖，以及可見缺陷的位置。對精準重現另保存尺寸與基準點檢查。不能用精細貼圖遮住大形問題；有意義的開口或薄片不因非封閉而自動判定失敗。

## 動態與互動結構

對可動零件檢查支點與階層；對變形資產檢查中性、中間值、最大幅度，以及可能同時出現的動作組合。檢查穿模、體積流失、法線、接縫及視線外側的結構。

先使用最小控制集合證明變形，再擴充細節。關卡通過需要實際姿勢或動畫證據，僅存在骨骼、形態鍵或動畫名稱不足以通過。

## 材質與表面

於中性照明和網站預期照明比較顏色、粗糙度、反射、透明及接縫。保留材質設定與貼圖來源，區分 base color、法線等不同資料的色彩處理。

圖像投射可能含原有陰影與高光。若採 PBR 重打光，需檢查光照疊加；若選擇 Unlit 或烘焙光照，則確認使用鏡頭與互動仍適合此策略。法線貼圖的細節不能作為輪廓與視差的替代品。

## 網站資產輸出

檔案型資產可使用 glTF Validator 檢查格式，以 glTF Transform 等工具檢查幾何、材質、貼圖與動畫成本。記錄工具版本、輸入輸出與設定，保留來源檔。

核對單位、軸向、支點、節點與控制名稱、材質、skin、morph 和動畫。網站端與匯出端採明確座標契約；不要以每次重新計算包圍盒覆蓋作者支點。

根據量測選用簡化、去重、量化或壓縮。優化可能改變節點結構、精度及動畫資料，操作後再驗證控制。壓縮貼圖時依色圖、法線與透明需求比較實際結果，並測試對應解碼器。

## 網站運行

在實際整合頁面檢查：

- 正式尺寸與響應式布局下的構圖、色彩、細節和可辨識度。
- 載入、錯誤狀態與必要的替代畫面；模型不得阻擋頁面主要內容。
- 相機、游標、點擊、滾動與動畫是否符合需求；有動態時提供適合的減少動態行為。
- 離屏、切背景與卸載時的動畫及資源生命週期。
- 目標裝置上的首次載入、穩態與最繁重動作，包含幀時間分布、渲染提交次數和記憶體相關指標。

`renderer.info` 可提供部分渲染統計，不能視為完整 GPU 時間或記憶體測量。記錄瀏覽器、裝置、視窗、像素比例、光照、快取及測量時間。可取得的指標有侷限時，按實際證據陳述結果。

瀏覽器自動截圖檢查視覺和功能；目標硬體測量評估效能。若只在 Headless 或桌面測試，手機效能維持尚待驗證。

## 修正回饋

| 缺陷 | 優先返回 |
| --- | --- |
| 輪廓、比例、背面結構錯誤 | 參考與幾何來源 |
| 動作塌陷、穿模、支點錯誤 | 拓撲、綁定或階層 |
| 貼圖接縫、光照疊加或質感失真 | UV、材質或打光 |
| 匯出後材質或控制遺失 | 匯出設定、格式支援與載入器 |
| 載入慢、渲染成本過高 | 依量測處理傳輸、解碼、幾何、材質或著色 |

每輪修正保留可比較證據。達到任務預算或重試限制後，交付最佳候選和未解缺陷，換來源或方法。正式交付附上各關卡狀態、剩餘限制、來源授權，以及可重建或繼續編輯的資料。
