# 製作路線與素材矩陣

## 選路線的條件

先判斷幾何從哪裡取得，再判斷需要何種控制。物件名稱只能提供線索，精準度、觀看距離與動態需求才決定製作方式。

| 條件 | 對路線的影響 |
| --- | --- |
| 必須符合尺寸或特定設計 | 優先使用尺寸圖、CAD、可量測的建模或可核對的既有來源 |
| 外觀概念優先且允許推定隱藏面 | 可用影像生成候選，先核對不同角度 |
| 需要分件操作 | 取得獨立零件與局部支點，保留組裝階層 |
| 需要自然變形 | 加入變形拓撲、權重、控制及極端姿勢驗證 |
| 只需程序效果 | 評估直接交付網站程式，或將部分結果烘焙為資產 |
| 大場景或大量重複物件 | 加入模組、實例、可見範圍與分批載入規劃 |

## 主要幾何來源

| 路線 | 最低必要素材 | AI 執行方式與工具候選 | 小樣本重點 | 失敗時的替代方法 |
| --- | --- | --- | --- | --- |
| 程序與 CAD | 關鍵尺寸、結構關係、外觀參考；精準重現時需可核對視圖 | Blender Python、Geometry Nodes；參數零件可用 CadQuery 或 build123d | 輪廓、曲面反射、尺寸與可修改性 | 改用細分曲面、既有 CAD 或局部基底；重新確認尺寸依據 |
| 影像轉 3D | 清楚主圖、風格目標；多圖需是外觀一致的同一設計 | 以 Meshy、Tripo、Rodin 等實際可用 API 產生候選，再匯入 Blender 檢查 | 灰模多角度、薄件、孔洞、分離部位與正反面一致性 | 修正輸入、換服務或基底、分件生成；難以重建處另行建模 |
| 既有基底改作 | 模型檔、授權、來源、材質及動畫說明 | 匯入 Blender 檢查網格、UV、階層、骨架與貼圖後局部改作 | 最難修改的部位與網站可載入性 | 更換基底、保留局部可用部分或混合製作 |
| 攝影測量與掃描 | 有覆蓋重疊的多角度照片、尺度；動態物體需符合捕捉條件 | RealityScan 或其他可操作重建工具，搭配 Blender 修整 | 難拍區域、孔洞、反光與重建尺度 | 補拍、調整捕捉方式或手動／程序補建；無法取得照片時改走其他來源 |
| 網站程序視覺 | 靜態與動態參考、變化規則、互動與目標裝置 | Three.js、Shader、實例化；可由 Geometry Nodes 輔助原型 | 正式尺寸的清晰度、動態節奏、著色成本與裝置相容性 | 簡化計算、降低更新頻率、混合預製幾何或改用預渲染媒體 |

工具名稱表示可評估方向，不表示已安裝、已授權或已通過本工作流測試。依[工具選擇](tooling.md)確認。

## 疊加控制與場景需求

| 分支 | 額外素材 | 優先驗證 | 應保留的結構 |
| --- | --- | --- | --- |
| 分件互動 | 拆件清單、組裝位置、旋轉軸、活動範圍 | 零件能獨立運作、相互遮擋正確、動畫不改變支點 | 局部座標、父子階層、語意命名 |
| 骨骼與表情 | 適合角色類型的中性姿勢、動作或表情參考、控制清單 | 中間值與極端變形、關節體積、穿模、輪廓 | 骨架、權重、形態鍵、綁定姿勢 |
| 大型場景 | 空間布局、觀看或行走範圍、重複物件、照明目標 | 可見集合、載入方式、實例化與遠近細節 | 場景分區、模組與必要的互動節點 |

靜態角色不必走完整骨架流程；可動產品也不必因此採用角色綁定。多個來源可混用，但接合處須核對尺度、材質與視覺風格。

## 素材準備分工

使用者提供目標、偏好、必須忠於的設計及可用預算。AI 可補充參考、整理視圖、提出設計草案、拆件和材質建議，並標示需要確認的假設。

- 外觀參考與尺寸依據分開記錄，避免把不同物件的照片當成同一件的測量。
- 多視角需檢查比例、部件數、圖案、姿勢與相機差異。生成圖的角度標籤不是校準證明。
- Image-to-3D 的背景、遮擋和打光要求依服務確認。保留原圖，衍生去背或簡化照明版本供比較。
- 真實物件掃描需要有重疊的照片覆蓋，不以少數概念正交圖取代。
- 動作素材需包含關鍵姿勢與活動幅度；只看中性姿勢無法證明變形品質。
- 每份素材記錄作者或來源、用途、授權、是否允許改作，以及是否會隨網站散布。

## 路線決定的交付

產出已填寫的需求模板，或等效的短規格，包含主要來源、疊加分支、小樣本、工具前提、預算與替代路線。資料不足時明確列出推定部位，先驗證會影響路線的核心問題。
